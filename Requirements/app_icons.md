# Alternate App Icons

## Agent summary

> Narrow tasks may stop here; open the related contracts for entitlement, localization, or asset work.

- **Scope:** iPhone/iPad alternate-icon catalog, Debug rollout flag, Unlimited Plays access, gallery behavior, Icon Composer packages, and system integration.
- **Must not break:** Classic remains the primary `nil` icon; system names are permanent; Release hides all feature UI and copy; disabling the flag never changes the installed icon.
- **Key files:** `AppIconCatalog`, `AppIconService`, `AppIconGalleryView`, `UIApplicationAppIconChanger`, `RetroRacingUniversal/Assets/RetroRapid*.icon`.

- Catalog order, IDs, package names, and non-`nil` system names are compatibility data and must not change after release.
- Classic uses `RetroRapid.icon`; its Default presentation remains visually equivalent to the shipped icon.
- Icon choice is independent from gameplay Style. Neither selection changes the other.
- The operating system's `alternateIconName` is authoritative; no duplicate selected-icon preference is stored.

## Platform and rollout

- The gallery is available when both the injected platform configuration enables it and the rollout flag is enabled. iPhone and iPad enable the platform configuration; macOS, watchOS, tvOS, and native visionOS disable it.
- UIKit system capability remains separate observable diagnostic state. It is refreshed after app activation, when Settings or the gallery appears, and at selection time, but a transient or environment-specific `supportsAlternateIcons == false` neither hides the iPhone/iPad gallery or Debug toggle nor preflights a configured-platform request. The platform adapter's actual `setAlternateIconName` result is authoritative and failures use localized recovery copy plus structured error-domain/code logging.
- iPhone and iPad inject `UIApplicationAppIconChanger` through a proxy that resolves `UIApplication.shared` after launch; SwiftUI `App` construction must not retain the singleton's pre-launch `nil` value. macOS, watchOS, tvOS, and native visionOS inject `UnsupportedAppIconChanger` or omit the shared surface. Platform decisions belong in composition roots, not shared views or service compile conditions.
- `DebugGameplayStorageKeys.alternateAppIconsEnabled` defaults on in Debug and respects its stored Debug override through one injected feature-flag dependency shared by the composition root, service, and Debug toggle.
- Builds without Debug features always resolve the flag to false, even if a prior Debug build stored true.
- Debug Settings shows **Enable alternate app icons** on configured iPhone/iPad builds even when the current environment reports that icon changes are unsupported.
- Alternate packages and generated `CFBundleAlternateIcons` declarations remain in Debug and Release products. Release hides the Settings row, gallery, Debug toggle, and icon-specific paywall benefit.
- Turning the flag off hides feature surfaces immediately but does not reset an installed alternate or call the system API.

## Access and selection

- Classic is always selectable and passes `nil` to the platform adapter.
- All nine alternates require Unlimited Plays.
- Cached returning-purchaser access permits selection while the first entitlement refresh is unresolved.
- Without cached access, unresolved alternates remain visible and disabled; no paywall is presented until resolution.
- A resolved free user can inspect every icon. Selecting a locked alternate opens the voluntary Unlimited Plays paywall.
- After entitlement revocation, an installed alternate remains selected. Classic stays available; other alternate changes remain locked.
- Selecting the current icon is a no-op. While a system request is active, repeated changes are rejected.
- The UIKit adapter is the sole owner of the system request lifecycle. It treats a matching `alternateIconName` as success even when the completion is withheld or reports cancellation, and accepts UIKit's successful completion when state publication is delayed. Apple's confirmation can keep the app inactive indefinitely, so inactive time never consumes the bounded recovery budget; only active time can produce a confirmed failure or timeout. The shared service awaits that result, refreshes from `alternateIconName`, and owns only observable progress and repeated-request suppression.
- On failure, preserve the system selection and show localized recovery copy.

## Gallery and accessibility

- Settings places an **App Icon** disclosure row inside Theme, directly after the Style controls, when the gallery is available. It does not duplicate the entry in a standalone section.
- The gallery mirrors the Style Gallery with a native `List` and ordered Classic, Themes, and Special Editions sections. Each option is a full-width preview button. Accessibility Dynamic Type sizes place the preview and state indicator together on the first line with the full-width name below, while capping the decorative preview at 180 points so more than artwork remains visible.
- Resolved free users see the same top-of-list Unlimited Plays prompt used by the Style Gallery. They can inspect every option, and selecting a locked alternate presents the voluntary paywall. Unlimited Plays users select alternates directly.
- Each of the eight adaptive-pilot previews keeps Default and Dark renditions together in one primary image set so both appearances remain inspectable in Xcode. The gallery always requests that canonical adaptive asset and changes the SwiftUI image view's identity when the color scheme changes, forcing a fresh catalog resolution without duplicating the Dark PNG under another asset name. Retro Game Box deliberately uses distinct light-grey/blue Default and black/red Dark covers. Classic and Polygon remain neutral Default references. Home Screen icon appearance is a separate system choice, so the gallery is representative rather than an authoritative report of SpringBoard's active treatment; the gallery does not add explanatory appearance copy above the choices.
- Every icon is one semantic `Button` with a localized name, visual description, selected/locked/changing state, and a non-color state indicator. Selected and locked/checking glyphs use system pink while retaining distinct checkmark, lock, and hourglass shapes.
- While one icon is changing, other rows retain normal contrast and focusability rather than inheriting a disabled appearance. Their accessibility value reports that another change is in progress, and service-level repeated-request suppression remains authoritative.
- Row separators align with the list content margin rather than the preview or text column.
- Preserve reading and focus order for VoiceOver, Voice Control, Switch Control, and Full Keyboard Access. Support Dynamic Type, Increase Contrast, and Differentiate Without Color.

## Icon Composer assets

- Keep every source unmasked and `1024×1024`; the system applies the icon mask.
- Each `.icon` package has no more than four groups and references only package-local layer assets.
- Each appearance remains recognizable as the same catalog option in Dark, Mono, Clear Light/Dark, and Tinted Light/Dark. Theme packages tune Composer materials without swapping subjects or composition. A Special Edition may use a deliberately different appearance-specific printing only when its shared identity, mask safety, source mapping, and visual contract are documented below.
- Pocket, LCD, Cartridge, CRT, and Disc are the layered theme pilot. Their packages place the car first and lane marks second in the foreground Subject group, with the road in the World group behind both. Pocket preserves the approved three-path interrupted-center composition; LCD, Cartridge, CRT, and Disc preserve four broad boundary paths. Every path and both road edges derive from the icon's shared vanishing point, extend from the top to the bottom edge, and grow in width, length, and spacing toward the viewer. The outer paths project beyond the lower corners and the inner paths remain visible around or below the car. Canonical iPad SpriteKit cars remain transparent, nearest-neighbour, opaque, glass-free layers.
- Pocket Default uses `#C8DC82` / `#AFC566` / `#5F6A36`; LCD Default uses `#F5EBD2` / `#ECE1C8` / `#8C8679`. Pocket Dark uses green-grey `#171B18` off-road and `#232A22` road fills with `#C8DC82` lane marks. LCD Dark uses warm-grey `#1B1A18` off-road and `#282622` road fills with `#F5EBD2` lane marks. Both surfaces remain dark while retaining a subtle trace of their Default palette; geometry is identical across appearances, and Mono hierarchy is expressed through Composer `tinted` annotations. Road and lane layers use Icon Composer's flat `image-name-specializations` entries: the entry without `appearance` is Default, `appearance: dark` selects the Dark companion, and `appearance: tinted` returns to Default for system mono rendering. Nested `slot` objects are invalid for the current Icon Composer document format and must be rejected because the renderer silently ignores them.
- Cartridge Default uses cool-grey `#A6A9B0` off-road, `#858990` road, and `#FFE000` lane marks. Cartridge Dark uses charcoal-blue `#191B21` off-road and `#272A31` road while retaining the characteristic yellow marks. Its four-path geometry and car placement remain identical across appearances.
- CRT Default uses green `#087D17` off-road, deep-navy `#151D29` road, and yellow `#FFD11A` lane marks. CRT Dark uses green-grey `#3A413B` off-road and charcoal-navy `#10141B` road while retaining yellow `#F6C928` marks. Its canonical 16-bit iPad car and four-path geometry remain identical across appearances. All four path centers remain inside the projected road polygon at every depth; the outer marks sit slightly inboard rather than straddling the off-road boundary. One frontmost transparent `Accents` layer combines the CRT scanlines, highlight lines, and radial edge falloff, ensuring the vignette survives Icon Composer's full composition instead of being visually lost as a backmost full-canvas layer. The effect is authored deterministically as SVG and rasterized before packaging because Icon Composer does not preserve every SVG pattern or radial-gradient feature. The `72%` radial falloff remains fully clear through `52%`, adds only a faint shoulder at `74%`, and then darkens more steeply through `89%` to the outer edge. Default uses `0.06` / `0.22` / `0.62` shoulder, mid, and edge opacity; Dark uses `0.05` / `0.18` / `0.58`, while reducing scanline opacity from `0.18` to `0.14`. This keeps the central composition at its authored brightness and concentrates the tube falloff in the mask-safe corner region.
- Mono annotations establish one shared hierarchy for Clear Light/Dark and Tinted Light/Dark across every layered theme package: the canonical car remains fully opaque, lane marks remain stronger than the road, and the road is the most translucent world layer. CRT keeps its combined frontmost scanline/vignette overlay at `0.60` opacity in Mono. Exact remaining Mono opacity is an authored Icon Composer tuning value rather than generated compatibility data; Default and Dark keep every artwork layer at full opacity. Use flat `opacity-specializations`; do not bake this hierarchy into replacement artwork.
- Retro Cartridge uses the approved opaque neutral-grey v5 concept PNG as Default and its approved opaque charcoal v5 companion as Dark. Retro Video Game uses the approved opaque v4 concept PNG as Default and its approved opaque v5 companion as Dark. Retro Game Box uses its approved opaque light-grey/blue v7 concept as Default and its approved opaque black/red v7 concept as Dark. Each package keeps one stable layer whose flat image-name specializations select `Default.png`, `Dark.png`, and Default again for Tinted. The document canvas for every Special Edition declares explicit Default, Dark, and Tinted fill specializations. Clear and Tinted remain system generated. These Special Editions deliberately prioritize the approved flattened renderings over semantic layer separation.
- Retro Cartridge Default uses neutral warm-grey molded plastic rather than cream: restrained grey midtones retain a faint warm undertone, microtexture, bevel highlights, and recessed shadows so the shell reads as physical ABS instead of metal or a flat tint. Its pink vent and piping, printed label, cream ink, car, projected road, accessibility seal, black recesses, gold contacts, composition, and mask-concentric geometry remain the established design. Dark retains the separately rendered charcoal shell.
- Retro Game Box presents two intentionally different printings of one original fictional 16-bit retail package. Default uses a very subtle warm light-grey paper texture, a full-bleed left identity band with an original upright condensed cobalt `A11y up to 11!` wordmark, and system-pink cartridge-style racing artwork that reaches the remaining raw square edges. A white lozenge with red outline and red `A11y up to 11!` lettering sits over the lower artwork; there is no footer or publisher sentence. It reuses the same gold `Accessibility up to 11!` seal artwork as the Dark source for consistency. Dark uses restrained matte-black cardboard grain and a period boxed-software hierarchy: a rectangular racing-art panel reaches the raw left edge, the `RetroRapid!` title overlaps its upper boundary, a red tab interrupts the top edge, and a separate black information rail occupies the right. A reduced original white capsule with red `A11y up to 11!` lettering stays inset at top right. A black callout with exact teal `Race like it is 1985` lettering overlaps the artwork and rail, while the exact gold accessibility seal occupies the lower-left safe region. The two-line footer lockup moves left as one unit, leaving a deliberate black gap after large red `ACCESSIBILITY UP TO 11` lettering and its cream-on-red `BUILT WITH LOVE BY` strip. A shorter, quieter muted-gold horizontal-line field runs through the raw bottom and right edges. Its black negative-space emblem uses a complete soft circle and a friendly no-neck human figure: the round head meets broad curved shoulders directly, with rounded open arms, torso, and legs. The raw square and system mask may crop the expendable outer line field while the emblem remains recognizable. Both appearances keep clean uninterrupted material through the raw square perimeter instead of edge wear, while clearly visible irregular fibrous interior scratches supply the skeuomorphic handled-box character. The scratches are asymmetrical, broken, and varied in angle; they must not trace the outer mask or damage critical text and marks. Both share the same brand, fake-front perspective, and coherent racing grammar. The unmasked square must read as a finished composition, while critical text and marks remain within the exact iOS 27 mask-safe region. Neither appearance may reproduce Nintendo, Game Boy, Super Nintendo, ESRB, or other third-party logos, typography, characters, exact layouts, or trade dress.
- Special Edition sources remain opaque, square, and full bleed. Validate their installed silhouette with `Plans/assets/alternate-app-icon-concepts/ios-27-icon-mask.png`, extracted from the supplied iOS 27 Photoshop template, rather than a guessed superellipse or ordinary rounded rectangle. Outer bevels and accent echoes must follow centered, evenly inset descendants of that continuous-corner mask; screen, label, connector, and control-tray surrounds may compress the same geometry but must retain its early shoulder transition and slope continuity. Boundary pixels stay matte and avoid near-white highlights that the system treatment could amplify into a pale rim.
- Disc uses the same semantic theme structure as the other layered packages: the canonical transparent 32-bit car and four perspective lane paths are in Subject, while appearance-specialized vector roads and the transparent circuit environment are in World. Default uses deep-teal off-road, pale-aqua `#CFEAEC` road, and `#073D4A` marks; Dark uses the same circuit environment with a charcoal-navy `#121E2B` road and aqua `#72E5E9` marks. The circuit layer is deterministically extracted from the approved v4 concept outside the shared projected road geometry, so no baked car or track pixels remain in that environment source. Polygon remains flattened with one neutral appearance. Classic is unchanged.
- Gallery previews are `512×512` ordinary image assets. Each imageset uses Xcode's universal single-scale representation rather than mislabelling the high-resolution source as an intrinsic `1x` bitmap. Each pilot imageset contains a Default and a luminosity-Dark rendition generated from the corresponding package sources; the resizable gallery always draws them smaller than their source dimensions.
- `./retrorapid assets app-icons` deterministically regenerates the Pocket/LCD/Cartridge/CRT/Disc SVG and canonical car layers, rasterizes CRT's transparent combined scanline/vignette overlays, derives Disc's transparent circuit environment from the approved v4 concept, copies all approved Special Edition sources into their packages, and generates the eight opaque RGB `512×512` adaptive gallery preview pairs. Each primary image set contains its inspectable Default and luminosity-Dark renditions; no duplicate appearance-specific image set is generated. `--dry-run` reports the mutation plan; `--check` rejects generated-output drift. Icon Composer appearance/material configuration remains in each tracked `icon.json` and is never overwritten by the generator.
- `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES` declares all nine alternates for Universal Debug and Release; Xcode generates Info.plist entries.

## Diagnostics

- `APP_ICON_SELECTION` records the gallery entitlement decision, `APP_ICON_CHANGE` records service/rollout state, and `APP_ICON_SYSTEM_REQUEST` records UIKit's requested/reported package names, application state, and whether system state or successful completion resolved the request.
- Failed operations include a stable reason plus structured error domain, code, and description fields. Do not log user data or wallpaper/Home Screen details.
- Capture the smallest relevant stream with `log stream --predicate 'eventMessage CONTAINS "APP_ICON_"' --level debug`.

## Testing

- Shared tests cover catalog order/uniqueness, stable mappings, policy states, flag isolation, success/failure/refresh, unconfigured-platform and disabled requests, stale capability snapshots, and repeated-tap suppression.
- Deterministic UI tests exercise the gallery button-to-service-to-selected-row observation path and verify that a resolved free user tapping a locked alternate opens the voluntary paywall. Universal adapter tests separately cover UIKit state confirmation, successful completion, failure, inactive confirmation time, and bounded active-state timeout so UI tests do not depend on SpringBoard's confirmation alert.
- The asset audit verifies package-local references, PNG/SVG dimensions, SVG view boxes, group limits and ordering, explicit document-level Default/Dark/Tinted fills, flat Default/Dark/Tinted image-name and opacity specializations, the absence of ignored nested specialization slots, adaptive preview appearance metadata, canonical generated-output drift, build-setting declarations, and shared catalog mappings. Full Release audit also verifies generated `CFBundleAlternateIcons`.
- Manual iPhone/iPad QA covers every icon and return to Classic, entitlement states, relaunch persistence, system surfaces, all adaptive appearances, representative wallpapers/tints, Dynamic Type, and assistive technologies.
